# 設計文件 — SDLCAIP1-40 前台文章詳細頁缺少返回首頁列表的連結

## 對應需求規格

G1 通過版本：作為前台訪客，我希望在文章詳細頁上有一個連結可以回到首頁
文章列表，讓讀完一篇文章後能繼續瀏覽其他文章，不需依賴瀏覽器上一頁。
驗收條件（Gherkin，共 4 條）：頁面新增一個連到 `/` 的連結、與既有「搜尋
文章」連結並存不互相取代、樣式套用既有連結規範（底線樣式，不另發明新
樣式）、既有測試（`tests/test_article_detail_page.py`、
`tests/e2e/test_article_detail_page_e2e.py`）全數維持通過。

範圍外：不含首頁列表頁本身變更、不含分頁狀態記憶（一律連回第 1 頁）、
不含相關文章推薦。

依賴：無。

## 介面/API 契約

無。本票不新增/變更任何對外 HTTP 端點或 request/response 格式，純粹是
`src/cms_aipilot/main.py` 中 `_generate_and_upload_static_page()`
產生的文章詳細頁靜態 HTML 內容新增一個 `<a>` 標籤。

## 資料模型

無新增資料模型。不涉及 DynamoDB 欄位、資料表或索引變更。

## 關鍵技術決策

- **插入點與確切標記**：於 `src/cms_aipilot/main.py`
  `_generate_and_upload_static_page()` 內，緊接在既有
  `'<a href="/search.html">搜尋文章</a>'`（目前第 218 行）**之前**，新增
  `'<a href="/">回文章列表</a>'`。連到 `/`（bucket 根目錄 index.html，即
  `_list_page_key(1)` 對應頁面），與既有「搜尋文章」連結相鄰並列，兩者
  皆保留、互不取代（對應 AC2）。順序選擇：新增連結放在前面，理由是
  「回列表」是本票要滿足的主要導覽需求，讓它在視覺閱讀順序上優先於既有
  次要功能（搜尋）；這只是同一層級兩個連結的先後順序，不影響任一連結
  的行為或可達性，非需要升級的產品決策。

- **不新增 CSS class、不新增樣式規則，沿用純文字連結的瀏覽器預設底線**：
  現有「搜尋文章」連結 `'<a href="/search.html">搜尋文章</a>'`
  本身未帶 `class`、詳細頁的 `_ARTICLE_DETAIL_PAGE_STYLE` 中也沒有任何
  `text-decoration: none` 規則作用於它，因此它呈現的就是瀏覽器對
  `<a>` 的預設底線樣式，直接符合 `docs/design-system.md` §7「連結：底線
  樣式……不用色塊或按鈕感包裝一般文字連結」的規範。新連結比照同一寫法
  （純 `<a>`，不帶 class、不加行內樣式），確保視覺與既有連結完全一致，
  不另外發明新樣式（對應 AC3）；同時是最小改動，不需修改
  `_ARTICLE_DETAIL_PAGE_STYLE`。

- **不動既有測試依賴的既有元素**：`<h1 class="article__title">`、
  `<time class="article__meta">`、`<div class="article__content">` 與既有
  搜尋連結的標籤、屬性、文字完全不變，只在其前面插入一個新的 `<a>`
  節點，既有測試若以文字/href 存在性斷言（而非位置相依的精確字串比對）
  應可維持通過；若既有測試對 `body` HTML 做整段字串相等比對而非局部
  斷言，開發者需同步更新該測試的期望字串以反映新增內容——這是實作既有
  測試以驗證新行為的正常更新，不是測試邏輯改變，不影響 AC4「既有測試
  不受影響」的意圖（既有斷言涵蓋的行為本身不變）。
